October 24 mobile regression repair: the earlier checks used trusted loopback origins and missed HTTP LAN access to Astro. Reproducing against the running dev server in Safari WebKit showed `isSecureContext === false` and no `crypto.subtle`; every new file was consequently rejected as an integrity mismatch. That caused detail sheets to auto-close and prevented recap opening. Hashing now uses native SHA-256 or `@noble/hashes` with the same truncated digest, without accepting unverified data. Native, absent, and failing Web Crypto are checked against Node's SHA-256 for empty, Unicode, and large inputs.

Detail requests now display loading/error state, keep the sheet open on failure, and support retry. Recaps no longer await the artwork/color datasets; late media updates preserve the active slide and player. Stale recap failures cannot close a newer open request. `mobile.json` records passing Safari WebKit touch checks against the actual HTTP dev server, including cold sheet navigation, story playback, blocked media, and corrupted data rejection/recovery. Those touch scenarios are also included in the Chromium build regression suite over an HTTP LAN origin. This is WebKit automation, not a physical iPhone run.
